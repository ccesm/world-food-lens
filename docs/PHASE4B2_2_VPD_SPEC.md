# Phase 4B-2.2 — VPD 与热×VPD 同现：方法与实现规格

状态：**已批准（2026-10-07，PR #8、#9）**。**2.2a 已上线**（PR #10）。VPD 气候缓存（D1–D8）和 2.2b 是 **Deferred — Advanced US Corn Research**：规格保留，恢复时直接从这里开始，不需要重新审批。
需要保持一致的文件：
- `PHASE4B0_CORN_AGRONOMIC_SPECIFICATION.md`：F 节（热与水分/VPD）、N 节（VPD 关卡）、O 节、P 节、Q 节
- `PHASE4B2_0_METHOD_SPEC.md`：B 节的共同约定
- `src/data/evidenceRegistry.json`：规则 `atmospheric_demand_vpd`、`heat_vpd_overlap`

## 1. 已确定的方案

1. **直接使用 gridMET 提供的 `vpd`**（日均饱和水汽压差，单位 kPa）。WFL 不自己从温度推算 VPD。
2. **分两步上线**：
   - **2.2a**：只发布 VPD 的描述性分布，不设阈值。**先上线。**
   - **2.2b**：发布热和 VPD 的同现判断，结果分三类：同时出现、未同时出现、未知。
3. **"高 VPD"的定义**：某个格点当天的 VPD 高于该格点 1991–2020 年同期的第 90 百分位。精确定义见第 4 节。
4. 气候基础设施**同时服务 2.2 和 2.3**，但 VPD 和降水的气候产品**各有独立的版本和哈希**（见 D8）。

## 2. 变量与数据来源

| 项目 | 规定 |
| --- | --- |
| 变量 | gridMET `vpd`，即 "mean vapor pressure deficit"，单位 kPa，日值。数据从 1979 年开始，空间分辨率约 4 km，和 `tmmx`、`tmmn`、`pr` 是同一提供方、同一格网 |
| 直接取用还是推算 | **直接取用提供方的产品**。gridMET 由 PRISM 和 NLDAS 合成，VPD 是提供方的派生变量，公开页面没有说明具体推算公式。WFL 不自己推算，也不用温度去近似 |
| 日界 | gridMET 定义的"日"是山地标准时间的午夜到午夜，对应 07 UTC。这与现有 Level C 一致，不重新聚合 |
| 初值修订 | 最近 60 天的数据是初值，之后会修订。沿用 Level C 的做法：每天重新检查，并记录数据源版本 |
| 实现前必须核对（失败即停） | 下载文件里的变量名（预计是 `mean_vapor_pressure_deficit`）、单位、全局属性和推算说明；与已有温度文件的格点几何完全一致；数据的可得历史。任何一项和预期不符，就不发布结果，而不是猜测 |

这满足 4B-0 的 VPD 关卡（N 节第 5 条）："湿度来源要经过验证，分辨率要匹配；缺失的 VPD 保持缺失"。
已知局限：提供方的推算细节没有公开。FAO-56 指出，用日平均温度计算饱和水汽压会带来偏差，
而我们无法确认提供方是否采用了这种做法。这一点要写进登记表的 `limitations`，并在页面上如实说明。

## 3. 2.2a — VPD 描述性分布（无阈值）

- **格点上**：14 天窗口内的日 VPD 平均值 `vpdDailyMeanKPa`，以及期内最大值 `vpdPeriodMaximumKPa`。
- **面积加权**：沿用 Level C 的做法，先在格点上计算，再按 2023 年 CDL 玉米面积加权。
  输出格式与 `weatherSummary` 相同，即 mean、min、max、p10、p50、p90。
- **覆盖率与分母**：格点只要在窗口内 14 天的 `vpd` 全部有效就计入，**和 Level C 的三个变量无关**，
  因为 VPD 是一个独立的证据维度。VPD 缺失的面积计入缺失面积，不按比例放大。
  分母是 Level C 的 `mappedCornAreaM2`，登记表的 `denominator` 字段与此一致。这个文件单独报告自己的覆盖率。
  2.1 用的是 Level C 的变量，所以覆盖率和 Level C 完全相同；这里不同。
- **证据等级**：概念是 A 级（大气蒸发需求，依据 M1、M2、U6）；实现是 B 级，因为使用的是提供方的派生产品。
  这一步**没有阈值**，`thresholdCategory` 记为 `physical`，`exactThresholdSupported` 记为 false。
- **允许的说法**："2023 年制图玉米面积上，14 天窗口内日均 VPD 的面积加权中位数为 X kPa。不区分生育期。"
- **禁止的说法**：
  - 任何 kPa 数值是伤害界限
  - "大气干旱导致减产"
  - 用温度推算出来的 VPD
  - 受影响面积或产量

## 4. 2.2b — 热×VPD 同现（已定：1991–2020 同期 P90）

本节的定义是**实现依据**。代码、测试和登记表参数都必须逐条对应；任何偏离都要发布新的方法版本。

### D1. 日历键与闰日
- 气候值按**日历键** `k = (月, 日)` 存储，共 365 个，**不包含 2 月 29 日**。
- 当天查键：日期 `t` 的键为 `(t.月, t.日)`；如果 `t` 是 2 月 29 日，使用 **2 月 28 日** 的键。
- 闰年的 2 月 29 日**作为普通样本日**进入跨越 2 月底的窗口（见 D2），不会被丢弃，也不会被重复计入。

### D2. 基准样本窗口
- 对键 `k` 和基准年 `y ∈ {1991, …, 2020}`，锚定日 `a(y, k)` 是 `y` 年的 `(月, 日)`。
  窗口 `W(y, k)` 是 `a − 7` 到 `a + 7` 的 15 个**实际日历日**。
- 落在基准期外的邻近日期也计入，包括 1990 年 12 月 25–31 日和 2021 年 1 月 1–7 日，这样每个键的样本数都相同。
- 格点 `c` 的样本集 `S(c, k)` 是 30 个窗口内所有日期的 gridMET `vpd` 值，名义上共 30 × 15 = **450 个**。

### D3. 百分位估计
- `P90(c, k)` 用 Hyndman–Fan 第 7 型（线性插值）估计第 0.90 分位数，基于 `S(c, k)` 中的有效样本，
  即 `numpy.quantile(values, 0.90, method="linear")`。
- 计算用 float64，使用提供方解码后的数值（已应用缩放和偏移）；结果以 float32 存储。
  比较时把存储的 float32 值转换为 float64 使用，以保证结果可复现。

### D4. 缺失样本
- 有效样本是指数值有限、且没有被提供方的缺测掩码标记的值。
- 有效样本数少于 **405 个**（450 的 90%）时，`P90(c, k)` 记为缺失，同时保存有效样本数 `validCount(c, k)`。
- 缺失的 P90 **永远不会用邻近日期或邻近格点代替**。
- 气候缓存的格点几何必须和当天天气的几何哈希完全一致；不一致时，整份气候缓存视为不可用，所有 V 都判为未知。

### D5. 高 VPD（V）
- 对格点 `c`、日期 `t`：如果 `vpd(c, t) > P90(c, key(t))`（**严格大于**），V 为真；如果小于或等于，V 为假；
  任一值缺失时，V 为未知。

### D6. 同日同现
- **热（H）**：对每个基准 `b ∈ {29, 30}°C`，`tmmx(c, t) > b` 时 H 为真，否则为假；`tmmx` 缺失时为未知。
  这两个基准**继承自 2.1** 已预先声明的 EDD 基准（登记表参数 `tmaxBaseC`，来源为 `heat_extreme_degree_days.parameters.baseC`），不是另行选定。
  在 single-sine 方法下，这等价于"当天 EDD_b > 0"，所以不需要 `tmmn`。
- **同一天**是指同一个 gridMET 日，即 07 UTC 到次日 07 UTC 的山地标准时间日，不做滞后，也不做滑动平滑。
  局限：VPD 是日平均值，H 用的是日最高温，所以这里是"同一天"同现，**不是同一小时**同现。
- **当日状态**按三值逻辑（Kleene 与）判定：
  - H 和 V 都为真：记为"同现"。
  - H 或 V 至少一个为假：记为"未同现"。即使另一个是未知，只要一个确定为假，就可以确定没有同现。
  - 其余情况：记为"未知"。

### D7. 窗口判定与面积口径
- 窗口就是 Level C 同一次运行的 14 天。每个格点的分类：
  - 至少有一天"同现"：判为**同时出现**。
  - 14 天全部"未同现"：判为**未同时出现**。
  - 其余情况：判为**未知**。
- **分母**是该州 Level C 的 `mappedCornAreaM2`，即 2023 年制图玉米面积。没有天气格点覆盖的剩余面积计入"未知"。
  三类各自所占的比例之和等于 1（容差 1e-9）。整个州失败时，该州全部面积计入"未知"。
  十州合并时把各州面积相加；如果某州的地理信息未知，合并结果的比例记为未知，不做归一化。
- **同现天数分布**：只统计 14 天中没有"未知"日的格点，按面积加权；这些格点占的面积单独报告。
- 每个基准 `b` 分别输出一组结果：`heatVpdCooccurrence29`、`heatVpdCooccurrence30`。

### D8. 气候缓存：两份独立产品
- 两份产品共用构建代码，但**版本和哈希各自独立**：
  - `gridmet-vpd-p90-1991-2020/1`：包含 `P90(c, k)`（float32）和 `validCount(c, k)`（uint16）。
  - `gridmet-pr-climatology-1991-2020/1`：降水统计量在 2.3 的规格中定义，本节不作规定。
- 每份产品都有自己的清单，包括：提供方源文件的校验和、天气几何哈希、构建器版本、D1–D4 的参数、
  每个州的内容哈希，以及缺失 P90 的数量。
- 它们由单独的工作流构建，做法类似 `corn-spatial-annual.yml`，然后发布为 Release 资产。
  通过 PR 把版本和哈希固定到配置文件后，才会被每日流程启用。
- 更新其中一份产品，不会影响另一份。每个输出文件都会记录自己用了哪一份的版本和哈希。
- **格点范围**：每个州天气几何内的全部格点，而不是只取有玉米的格点。这样以后更换作物地图，不会使气候缓存失效。
  如果实测体积超出预算，就改为只保留有玉米的格点，并绑定到 `annualKey`，同时在报告里说明。
- 每日流程**只读取**缓存，从不重新计算 30 年的气候值。

### 依据与分级
- P90 相对于当地同期气候，是"异常偏高"的统计定义，不声称任何生理阈值。
- 分位数的取值（0.90）、窗口宽度（±7 天）、最少样本数（405 个）都属于 C 级启发式，在登记表的 `heuristicComponent` 中逐项写明。
- 2012–2019 年只用于开发；这些参数不根据任何产量结果去调整。

### 已否决的方案（记录在案）
- 项目自定的固定 kPa 阈值：2026-10-07 未被采纳，理由见 4B-0 Q 节，即 VPD 没有通用的 kPa 伤害界限。

## 4a. 2.2a 实现说明

- VPD 在 Level C 和热量文件都写出**之后**才下载，使用**独立的网络预算**（`--vpd-network-budget-seconds`，默认 120 秒）。
  所以 VPD 下载失败或超时，不会占用 Level C 的 180 秒预算，也不会改变 Level C 的任何结果。
- 变量名 `mean_vapor_pressure_deficit` 和单位 `kPa` 都从登记表读取。读取时还要核对坐标、日期、几何是否与年度作物格网一致，
  并做数值的合理范围检查（0–15 kPa，只用于检查文件格式，不是生理范围）。任何一项不符就判为不可用，不做猜测。
- 用历史固定输入重放时（`--offline-raw`），不写 VPD 文件，因为固定输入里没有 VPD。
- 每次运行都会在 GitHub Actions 里留下一条 `VPD screen` 注释，写明覆盖率、不可用的州和原因，不用看日志也能核对结果。
- 局限：VPD 的原始下载文件**不**放进 Level C 的输入存档（`archive_inputs`），但它的哈希和版本会记录在
  `corn-vpd-screen.json` 的 `weatherVersions` 中。

## 5. 版本与文件

- 方法版本：`mapped-corn-vpd-screen/1`。输出写入新文件 `public/data/corn-vpd-screen.json`，
  用 `baseArtifact.analysisHash` 绑定 Level C。`corn-spatial.json` 和 `corn-heat-screen.json` 保持逐字节不变。
- VPD 作为新增的下载变量。修改 `corn_spatial*.py` 或 `refresh_corn_spatial.py` 会改变 Actions 天气缓存的键名，
  因为键名里包含这些脚本的哈希。所以**第一次运行需要冷启动下载**。
  2026-10-07 那次故障就是在冷启动时遇到 gridMET 暂时无响应。因此合并前要先在分支上用
  `validation_only` 跑一遍，并估算下载时间是否在 180 秒的网络预算之内。
- 改动 `VARIABLES` 有一个风险：`summarize` 的联合有效性会把 `vpd` 也算进去，
  这会改变 **Level C 本身**的覆盖率。为保证 `corn-spatial.json` 不变，Level C 的指标必须继续只基于原来三个变量计算。
  VPD 单独读取、单独计算有效性。这一点由测试保证：同一组输入下，`corn-spatial.json` 的内容逐字节相同。
- 登记表：`atmospheric_demand_vpd` 补上输出名、参数和局限，随 2.2a 改为 `reviewed`。
  `heat_vpd_overlap` 随 2.2b 改为 `reviewed`，参数为 `quantile: 0.90`、`quantileMethod: hyndman-fan-7`、
  `baselinePeriod: 1991-2020`、`windowHalfWidthDays: 7`、`minimumValidSamples: 405`、`tmaxBaseC: [29, 30]`（继承自 2.1，有测试强制一致），
  以及 VPD 气候产品的版本和哈希。
- 告警和邮件：不改。新文件不是告警输入，不进入 `inputsHash`。

## 6. 测试与验收（对照九项完成标准）

- **单元测试**：
  - VPD 的面积加权统计。
  - D1 键映射（含 2 月 29 日）、D2 窗口跨年和跨闰日、D3 与 `numpy.quantile` 一致、D4 少于 405 个样本时为缺失、D5 严格大于、D6 三值逻辑的全部 9 种组合。
  - 同现三类的判定，包括"有一天同时出现，但其他天有缺失"仍判为"同时出现"。
  - 全部数据完整且没有同时出现，判为"未同时出现"。
  - 有缺失且没有同时出现，判为"未知"。
  - 三类比例相加等于 1。
- **空间测试**：VPD 格网和温度格网不一致时，失败即停；不同州的数据可以正确合并。
- **缺失与部分覆盖**：某个日期整天缺 VPD；单个州取数失败；整体失败时写出"全部不可用"的文件。
- **不变性**：同一组输入下，`corn-spatial.json` 和 `corn-heat-screen.json` 逐字节不变。
- **固定输入**：用合成的 netCDF 文件做确定性测试。
- **真实数据合理性检查**：在分支上用 `validation_only` 跑一次，合并后读取第一份生产数据，写进 2.2 的报告。
- **登记表**：所有输出都必须属于 `reviewed` 规则，否则测试失败（现有闸门会自动检查）。
