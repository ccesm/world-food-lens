# G1.0 — Global Crop Supply Contract（全球作物供需数据契约）

状态：**草案，待审阅**（2026-10-07）。本阶段只定义数据语义、校验规则和解读规则，**不解析新的生产数据**（那是 G1.1 的工作）。
机器可读契约：`src/data/globalSupplyContract.json`；辅助函数和校验器：`src/services/globalSupply.js`；
测试：`tests/globalSupplyContract.test.js`。上级路线：`GLOBAL_FOOD_INTELLIGENCE_ROADMAP.md`。

## 0. 依据：实际核对过的数据

这份契约建立在实际数据上，没有按字段名去猜：

- **PSD 结构审计**（`scripts/g1_psd_audit.py`，冻结结果在 `tests/fixtures/g1-psd-structure-audit.json`）：
  在 GitHub Actions 中下载了 USDA PSD 的谷物文件和油籽文件（运行 37702352394），只读，不发布任何数据。
- **修订审计**（`scripts/g1_revision_audit.py`，冻结结果在 `tests/fixtures/g1-revision-audit.json`）：
  扫描仓库 git 历史中每一个 `official-data.json`。

审计确认的事实：

| 事实 | 对契约的影响 |
| --- | --- |
| 两类批量文件中的四作物共用列：`Commodity_Code`、`Country_Code`、`Market_Year`、`Calendar_Year`、`Month`、`Attribute_ID`、`Attribute_Description`、`Unit_ID`、`Unit_Description`、`Value` | 按 **ID** 映射（属性 ID、单位 ID），描述文字只用来核对 |
| 单位：`(1000 MT)`（ID 08）、`(1000 HA)`（ID 04）、`(MT/HA)`（ID 26） | 本来就是规范单位，第一版换算为恒等；单位一旦变化，该作物判为不可用 |
| 每个"国家 × 年份 × 属性"都有一行；不生产的地方填 0 | **PSD 是补零矩阵**：0 和"没有报告"无法区分 |
| 国家代码是 FAS 的两位代码（CH 是中国，UP 是乌克兰，RS 是俄罗斯），**不是 ISO 代码** | `isoCode` 必须显式映射，默认为 null |
| `E4`（欧盟）从 1999 年开始；`E2`（EU-15）到 1998 年；成员国单独的数据只到 1998 年；`UK` 从 2016 年开始 | 欧盟是 bloc，不是国家；两个欧盟代码不能同时计入 |
| **批量 CSV 没有世界合计行** | WFL 加总只能是交叉核对或明确标注的后备。可获得且可比的 USDA 官方世界合计优先作为未来规范值 |
| 当前四作物最新市场年度的发布元数据为 2026-09；历史行有较早的最后更新月份 | 原始文件不是完整的历次发布快照；文件快照发布期与行级最后更新月份分开保存 |
| 大豆的国内消费有 3 行负数，饲料损耗有 5 行负数 | 数据质量异常，需要明确的处理规则 |
| 贸易有两种口径：市场年度（`Exports` 088、`Imports` 057）和贸易年度（`TY Exports` 113、`TY Imports` 081） | 两者概念不同，第一版只映射市场年度 |
| 稻米：`Production` 是精米；`Rough Production`（054）是另一个属性 | 稻米按精米计；单产的计量基础要在 G1.1 核对 |

## 1. 观测身份

| 层级 | 格式 | 示例 |
| --- | --- | --- |
| 观测 | `g1:{commodity}:{geographyId}:{marketingYearSourceId}:{metric}` | `g1:corn:usda-psd:BR:2026:production` |
| 某一期发布的观测 | `{observationId}@{source}:{sourceRelease}` | `…@usda-psd:2026-09` |
| 修订 | `{observationId}@{source}:{previousRelease}->{currentRelease}` | `…@usda-psd:2026-09->2026-10` |
| 数据发布 | 沿用现有的不可变发布（`release-manifest.json` 的 `releaseId` 和数据提交） | **不另建一套发布身份** |

所有 ID 都由代码组成，不用显示名称。`sourceRelease` 是经核验的文件快照发布期，
由当前/最新市场年度的发布元数据识别。历史行的 `Calendar_Year-Month` 另存为
`rowLastUpdatedMonth`，不强制改写为快照月份。

**版本单调性**：同一 `observationId + source + sourceDataset` 的新快照不得比已接受发布期旧；
`retrievedAt` 和缓存时间不决定顺序。`assessReleaseVersion()` 是纯验收/隔离判断，拒绝时明确返回
`retained`，不写数据。相同发布期、相同原始哈希是 unchanged；同月不同字节仅在有来源认证的
`revisionSequence` 严格递增时接受，否则隔离并保留旧数据。现有批量文件未提供这种来源内修订序号，
不能用抓取次数、哈希排序或 HTTP 时间冒充；未来 G1.1 必须落实持久化验收，本阶段不接入生产。

## 2. 作物

`corn`、`wheat`、`rice`、`soybean` 四种从一开始就都受支持。G1.1 实现前三种（同一个谷物文件），G1.2 实现大豆（油籽文件）。
稻米的产量按**精米**计，并在页面上写明。

## 3. 地理

| 类型 | ID | 说明 |
| --- | --- | --- |
| `country` | `usda-psd:{FAS code}` | 登记表里没有列出的 PSD 代码，默认是 country；`isoCode` 在显式映射前为 null |
| `bloc` | `usda-psd:E4`、`usda-psd:E2` | 欧盟作为整体统计，成员国构成随时间变化；E2 和 E4 永远不会同时计入 |
| `world` | `wfl:world` | **派生后备 / 交叉核对**：通过覆盖校验的 PSD 地理单元之和，欧盟只计一次。它不是 USDA 的官方世界合计 |

类型**只**按代码从登记表中确定，绝不从名称推断。测试保证：名字叫"European Union"、代码不在登记表里的地区，仍然是 country。

**世界合计来源政策**：未来优先采用可获得、且作物、计量基础、单位、市场年度和发布期可比的
USDA 官方世界合计（例如官方 PSD 世界系列或官方报告），而不是把 WFL 加总升级成官方值。
没有 API key **不阻塞 G1.1**；官方世界系列不可访问时，可使用明确标注、覆盖经校验的 WFL 后备。
官方和派生系列保留各自身份与来源，不静默拼接；这只是来源政策，G1.0 不新增 API 或报告解析器。

**覆盖与欧盟规则**：`assessGeographyCoverage()` 针对单个作物/市场年度/指标的规范化观测，
用显式、经审核且版本化的 `expectedIds` 检查国家是否完整存在。没有基线为 unknown。
源零值算已报告行，但不是“真实不存在”的证明；缺行/缺值不算覆盖。任何缺失国家都列出且阻止
该派生合计被标为完整，不能因为剩余国家仍加总到一个合理数值就放行。
E4 从 1999 年起使用，之前使用 E2，UK 从 2016 年起单列；若应有欧盟聚合，不能用成员国替代
缺失聚合。成员国排除只按调用方提供的、经审核的 `euMemberIds`，不按名字猜。
诊断中的 `geographyCountCoverage` 是**地理行数覆盖率**，不是生产份额；不外推、不归一化。
第一版最新年度测试基线来自冻结审计；历史年份/欧盟成员口径必须单独审核，不伪称历史地图。

## 4. 市场年度

- 保存三样东西：来源 ID（PSD 用整数起始年，例如 `2026`）、显示标签（`2026/27`）、来源系统（`usda-psd`）。
- `startMonth` 默认为 **null**。只有在有经过审核的来源表时才填写，绝不推测。
- 各国、各作物的市场年度起始月不同，所以不同国家的 2026/27 **不是**同一段时间。以后做跨国比较的页面，必须显示这一限制。

## 5. 指标

| 指标 | 规范单位 | PSD 属性 / 单位 ID | 0 是否有效 | 负数 | 方向 | 极性 | 汇总核心 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| production | 1000 t | 028 / 08 | 是（补零，带标记） | 无效 | 有 | 越低越紧 | 是 |
| harvestedArea | 1000 ha | 004 / 04 | 是 | 无效 | 有 | 越低越紧 | 否（是产量的组成部分） |
| yield | t/ha | 184 / 26 | 面积为 0 时记为 not-applicable；面积大于 0 时标记 | 无效 | 有 | 越低越紧 | 否（是产量的组成部分） |
| beginningStocks | 1000 t | 020 / 08 | 是 | 无效 | 有 | 越低越紧 | 否（等于上一年的期末库存） |
| endingStocks | 1000 t | 176 / 08 | 是 | 无效 | 有 | 越低越紧 | 是 |
| domesticUse | 1000 t | 125 / 08 | 是 | 保留并标记（大豆有负数） | **不适用** | 情境性 | 否 |
| exports | 1000 t | 088 / 08（市场年度） | 是 | 无效 | **不适用** | 情境性 | 否 |
| imports | 1000 t | 057 / 08（市场年度） | 是 | 无效 | **不适用** | 情境性 | 否 |
| stocksToUse | % | 派生 | 是 | 不适用 | 有 | 越低越紧 | 否（复用期末库存） |

- **stocksToUse = endingStocks ÷ domesticUse × 100**，与现有的世界指标定义一致。
  分母缺失、为 0、为负或不适用时，结果为 **unknown**。
  对出口国来说，这个比值没有考虑出口需求，页面上要说明。
- **domesticUse 为什么不给极性**：消费上升可能意味着需求压力，也可能只是供应增加后用得更多，例如饲料用量。
  没有单独论证之前，这个指标只作为背景展示。如果以后要给它定极性，需要另提理由交审阅。
- **出口和进口**：同样的变化，对出口国和进口国含义相反，也可能反映需求而不是供应，所以只显示数值、修订和同比，不贴方向标签。
- **单位换算**：来源单位必须和映射完全一致，否则判为不可用，不做静默换算。第一版是恒等换算，由测试固定。

## 6. 状态分类

| 状态 | 含义 | 和相近状态的区别 |
| --- | --- | --- |
| `ok` | 有值、通过校验、来自当前应有的发布期 | — |
| `missing` | 这一期发布里**确实没有**这个值（没有这一行） | 不是 0。PSD 是补零矩阵，所以 PSD 很少出现 missing |
| `unavailable` | **获取、解析或校验失败**，例如单位变了、出现了不可能的负数 | 是系统的问题，不是来源没给值。可以作用于整个作物，也可以作用于单条观测 |
| `stale` | 值有效，但发布期比应有的更新节奏旧 | 不等于错误 |
| `not-applicable` | 概念本身不适用，例如面积为 0 时的单产、情境性指标的方向 | 不是缺数据 |
| `conflicting` | 两个同等级的来源给出不同的值；全部显示，不替用户挑选 | — |
| `unknown` | **只用于派生值、修订和方向**：无法计算，例如没有上一期、基数为 0、死区还没设定 | 不能用 0 代替 |

## 7. 修订模型

| 字段 | 定义 |
| --- | --- |
| `currentEstimate`、`previousEstimate`、`revision`、`revisionPct` | **同一观测**在相邻两期发布之间的变化，即"对同一年的新信息" |
| `yoyChange`、`yoyPct` | **同一期发布**里，本年与上一年的差，即"两个不同年份的比较" |

- 第一次出现的观测没有上一期，所以修订是 **unknown**，**不是 0**。
- 基数为 0 时，百分比是 unknown。
- 修订和同比是两个独立的字段，各自有各自的方向，不能混用。

## 8. 修订审计（实际结果）

**结果：仓库历史里能比较的"发布对"是 0 个。**

- 扫描了 56 个包含 USDA 数据的提交，只找到一个发布期（`2026-09`）。
- 现有解析器只保留产量、消费、期末库存和库存消费比，所以面积和单产即使有修订历史，也不可能出现在里面。
- 最新市场年度发布期为 2026-09；较早历史行的最后更新月份不是完整发布快照。

因此，**目前没有任何数据可以用来校准修订的死区**，这里不编造分布。

作为补充背景，下面是结构审计中**同比**变化幅度的分布。它来自当前一期内 2000 年以后的历史，包括所有国家（含小国），**没有加权**。
小基数会造成极端值（例如小麦进口的同比最大值达到 361,600%），所以**它不能直接用作修订的死区**：

| 绝对同比 % | 玉米 p50 / p75 / p90 | 小麦 p50 / p75 / p90 | 稻米 p50 / p75 / p90 | 大豆 p50 / p75 / p90 |
| --- | --- | --- | --- | --- |
| 产量 | 8.7 / 21.5 / 45.3 | 11.1 / 27.3 / 52.2 | 7.2 / 17.6 / 33.8 | 8.6 / 25.0 / 50.0 |
| 单产 | 5.7 / 15.2 / 33.1 | 8.2 / 20.6 / 40.0 | 4.4 / 10.2 / 21.9 | 5.1 / 15.1 / 30.3 |
| 收获面积 | 5.3 / 13.3 / 29.7 | 5.3 / 13.9 / 29.6 | 4.6 / 13.5 / 26.7 | 6.4 / 17.7 / 42.9 |
| 期末库存 | 23.1 / 47.9 / 88.8 | 23.2 / 47.7 / 84.6 | 22.7 / 46.2 / 80.3 | 33.3 / 72.2 / 130.3 |

已识别的数据质量问题：
- 补零矩阵。
- 大豆国内消费有负数。
- 欧盟的地理口径有 E2 和 E4 的切换。
- 英国从 2016 年起单独列出。
- 小基数百分比不稳定。

## 9. 方向规则（草案）

- 方向**只针对单个、有资格的指标**，取值为 tightening、stable、easing、unknown 或 not-applicable。**不做多指标的数值分数。**
- 对"越低越紧"的指标：变化 < −死区，判为 tightening；变化 > +死区，判为 easing；**|变化| ≤ 死区（含边界），判为 stable**。
- 修订方向和同比方向分开计算，各自用各自的死区。
- **死区还没有设定**（`deadZonesPct: {revision: null, yoy: null}`）。在死区设定之前，方向一律输出 **unknown**。

**死区方案提议**（交审阅，不是最终值）：
1. **形式**：每个指标一个固定百分比（第一版不按作物细分，除非审计显示作物之间差异很大）。不用自适应或机器学习阈值。
2. **小基数保护**：只在基数不低于某个下限时才给方向，避免小国的小数字产生极端百分比。下限的取值（例如基数至少占世界的一定份额）需要和死区一起审定。
3. **校准数据从哪里来**：USDA 下一次发布是 **2026 年 10 月 9 日的 WASDE**，PSD 批量文件可能会在之后一天更新。
   G1.1 上线后，每一期发布都会提供约 120 个国家 × 每种作物、全部指标的完整修订截面。
   第一期新发布之后，运行 `scripts/g1_revision_audit.py`（届时扩展到 G1.1 保留的全部字段），
   按指标统计 |修订%| 的分位数，再按事先说好的规则提出数值，例如"取主产国 |修订%| 的中位数，向上取整到 0.5%"。
   最后由你审定后冻结。
4. **可选**：如果想在 10 月之前就有依据，可以另做一次只读的历史审计，使用 USDA 公开的 WASDE 历史数据。这需要你决定（见第 15 节）。

所有死区和小基数下限都是 **C 级解读启发式**，登记在契约的 `interpretationRules` 中（`g1_metric_direction`，状态 draft）。

## 10. 汇总供应状态（草案，暂不采用）

- 只汇总**核心指标**的方向，不加权，也不打分；输出总是列出每个指标及其方向。
- 提议的规则（`g1_aggregate_supply_status`，状态 draft）：
  - 有任一核心指标的方向为 unknown：判为 **unknown**。
  - 既有 tightening 又有 easing：判为 **mixed**。
  - 有 tightening、没有 easing：判为 **tightening**。
  - 有 easing、没有 tightening：判为 **easing**。
  - 其余情况：判为 **stable**。
- 面积和单产是产量的组成部分，期初库存等于上一年的期末库存，所以**不计入核心**，以免同一个信号被重复计算。
- **已指定核心**：仅 production 和 endingStocks。`stocksToUse.inAggregateCore = false`，
  作为单独背景指标保留，避免重复库存证据。死区、解读阈值和汇总规则仍**保持 draft**，
  生产方向保持 unknown，G1.1 不会展示未经审定的汇总状态。

## 11. 来源冲突

- 键为"作物 × 地理 × 市场年度 × 指标"，可以挂多个来源的观测，每个都保存来源、等级、发布期、来源日期和数值。
- `resolveSources()` 只使用状态 ok 的有限数值；过时、缺失、无效证据仍保留但不作为当前比较值。
- 优先级为 Tier 1 → Tier 2 → Tier 3。低等级证据保留在 `lowerPriority`，不能覆盖高等级证据，
  也不构成同等级冲突。未知来源等级返回 unknown，不猜测优先级。
- 最高可用等级的观测须具有相同 `observationId`、`unit`（规范单位）、`basis`（计量基础）、
  `comparisonPeriod`（明确可比的年度/时间口径）和 `sourceRelease`（第一版 YYYY-MM）。
  缺这些字段或值不同均为 **unknown / not comparable**，不能把新旧发布差异叫作来源冲突。
  不同国家的同名市场年度也不自动满足时间可比性。
- 只有上述元数据完整且可比的同等级**不同来源**数值不一致才记 **conflicting**；全部显示，不自动挑选。
  同一来源的不同数值应先通过修订顺序验收，不在此函数猜测哪个版本更新。
- 第一版只有 USDA PSD 一个来源；辅助函数不接入生产，尚未新增第二个数据源。

## 12. 数据来源记录

每个作物块都记录：`source`、`sourceDataset`、`sourceRelease`、`sourceDate`、`retrievedAt`、`rawFileHash`、`dataRevision`。
数据健康沿用现有的数据契约记录。`dataRevision` 和 `releaseId` 来自现有的发布流程，不另建一套。

## 13. 失败隔离

- 玉米、小麦、稻米**各自解析、各自校验、各自发布状态**。一种作物失败，既不会让另外两种失败，也不会被它们的成功掩盖。
- 索引文件**不允许有整个文件级别的状态**，校验器会拒绝。必须能表达"玉米正常、小麦不可用、稻米正常"这样的结果。

## 14. 文件结构

| 文件 | 内容 |
| --- | --- |
| `public/data/global-supply.json` | 索引：契约版本，以及每种作物的状态、发布期、来源记录和数据文件路径 |
